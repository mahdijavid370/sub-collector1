# جمع‌آوری اشتراک VLESS

این پروژه لینک‌های VLESS را از چند اشتراک جمع‌آوری، تکراری‌ها را حذف و فایل پیکربندی Xray را تولید می‌کند. برای جمع‌آوری فقط Python 3.10 یا جدیدتر لازم است و وابستگی دیگری نصب نمی‌شود؛ استفاده و سنجش محلی پیکربندی به Xray نیز نیاز دارد.

## تنظیم سکرت `SUB_URLS`

در GitHub به **Settings → Secrets and variables → Actions → New repository secret** بروید. نام سکرت را دقیقاً `SUB_URLS` بگذارید و در مقدار آن، نشانی اشتراک‌های HTTP یا HTTPS را، هر کدام در یک خط، وارد کنید:

```text
https://example.com/subscription-one
https://example.org/subscription-two
```

خط خالی و خطوطی که با `#` شروع شوند نادیده گرفته می‌شوند. هر منبع باید حداقل یک لینک معتبر VLESS داشته باشد. مقدار سکرت را در فایل‌های مخزن قرار ندهید؛ آدرس منابع و لینک‌های دریافتی نیز در لاگ چاپ نمی‌شوند.

> **توجه امنیتی:** فایل‌های خروجی حاوی خود لینک‌های VLESS، شناسه‌ها و آدرس سرورها هستند و طبق تنظیم فعلی در مخزن commit می‌شوند. اگر مخزن عمومی باشد، این اطلاعات برای همه قابل مشاهده خواهند بود.

## اجرای خودکار و دستی

ورک‌فلو هر چهار ساعت، در دقیقهٔ ۱۷ و ساعت‌های `00، 04، 08، 12، 16، 20` به وقت **UTC** اجرا می‌شود. GitHub زمان‌بندی را فقط روی شاخهٔ پیش‌فرض اجرا می‌کند و ممکن است اجراها را به تعویق بیندازد یا در زمان شلوغی حذف کند. برای فعال‌شدن تغییرات این ورک‌فلو، آن‌ها را ابتدا به شاخهٔ پیش‌فرض منتقل کنید. همچنین از صفحهٔ **Actions → Auto Update Subscription Configs → Run workflow** می‌توان آن را دستی اجرا کرد.

ورک‌فلو پس از اجرای تست‌ها و جمع‌آوری، خروجی را با Xray نسخهٔ `v26.10.29` اعتبارسنجی می‌کند؛ فایل رسمی با SHA-256 بررسی می‌شود و در صورت شکست اعتبارسنجی چیزی commit نخواهد شد. دسترسی نوشتن `GITHUB_TOKEN` برای commit و push لازم است. اگر مخزن یا سازمان این دسترسی را محدود کرده باشد، در تنظیمات Actions اجازهٔ نوشتن را فعال کنید. اجراهای هم‌زمان روی یک شاخه با هم تداخل نمی‌کنند.

برای اجرای محلی، مقدار همان سکرت را در متغیر محیطی قرار دهید؛ برای مثال اگر فایل محلی حاوی URLها نامش `SUB_URLS` است:

```bash
SUB_URLS="$(cat /path/to/SUB_URLS)" python collector.py
```

این فایل محلی نباید در Git ثبت شود. نام `/SUB_URLS` در ریشهٔ مخزن در `.gitignore` قرار گرفته است.

## خروجی‌ها و رفتار خطا

- `javidsub`: لینک‌های معتبر VLESS، به صورت متن معمولی و هر لینک در یک خط.
- `json_configs/configs_N.json`: همان لینک‌ها در بخش‌های حداکثر ۱۰۰۰تایی؛ بخش‌های قدیمی و اضافی حذف می‌شوند.
- `final_sub.txt`: **JSON معمولی Xray، نه Base64**، شامل outboundهای قابل تبدیل، انتخاب خودکار و تنظیمات مسیریابی. برای قوانین `geoip` و `geosite` باید فایل‌های دادهٔ مربوطه در نصب Xray موجود باشند. Xray نسخهٔ `v26.10.29` فایل معمولی با پسوند `.txt` را حتی با گزینهٔ `-format json` مستقیماً نمی‌پذیرد؛ برای آزمایش، آن را از ورودی استاندارد بخوانید: `xray run -test -format json -c stdin: < final_sub.txt`. برای اجرا، همین دستور را بدون `-test` به کار ببرید. اگر برنامهٔ شما فقط فایل با پسوند `.json` می‌پذیرد، یک کپی محرمانه با آن پسوند خارج از مخزن بسازید.

اشتراک‌های متنی و Base64 استاندارد یا URL-safe پشتیبانی می‌شوند. تبدیل JSON از TCP، WebSocket، gRPC، XHTTP، HTTPUpgrade و mKCP و تنظیمات رایج TLS، Reality و Vision پشتیبانی می‌کند. تنظیمات mKCP بر پایهٔ `finalmask` نسخهٔ `v26.10.29` است و ممکن است در نسخه‌های قدیمی‌تر Xray قابل بارگذاری نباشد. لینک‌هایی که برنامه تنظیمات نامعتبر یا امکانات پشتیبانی‌نشدهٔ آن‌ها را تشخیص دهد در خروجی خام باقی می‌مانند ولی وارد JSON نمی‌شوند؛ نسخه‌های جدید Xray اتصال VLESS بدون TLS یا رمزگذاری به آدرس عمومی و همچنین TLS با `allowInsecure=true` را رد می‌کنند؛ این لینک‌ها نیز در JSON قرار نمی‌گیرند. در دسترس بودن سرورها و سازگاری همهٔ تنظیمات اختصاصی ارائه‌دهنده تضمین نمی‌شود.

اگر سکرت خالی باشد، دریافت هر کدام از منابع شکست بخورد، منبعی VLESS معتبر نداشته باشد یا هیچ لینک قابل تبدیل به Xray پیدا نشود، برنامه با کد خطای غیرصفر متوقف می‌شود و فایل‌های قبلی جایگزین نمی‌شوند. برای خطاهای موقت شبکه چند بار تلاش می‌شود. در نتیجه یک پاسخ خالی یا خطای موقت، اشتراک قبلی را پاک نمی‌کند.

## انتخاب اتصال و بهبود سرعت

فایل `final_sub.txt` برای استفاده در برنامه‌ای است که پیکربندی کامل Xray و `burstObservatory` و balancer را پشتیبانی کند. Xray روی **شبکهٔ دستگاه شما** زمان پاسخ هر outbound را با یک درخواست کوچک `HEAD` به `https://www.gstatic.com/generate_204` می‌سنجد و بین گره‌های پاسخ‌گو، گزینهٔ کم‌تأخیرتر را انتخاب می‌کند. در شروع، همهٔ گره‌ها یک‌بار هم‌زمان بررسی می‌شوند؛ سپس زمان آزمون‌ها تصادفی پخش می‌شود. برای حداکثر ۹۰ گره، میانگین فاصلهٔ آزمون هر گره ۴۵ ثانیه است؛ با گره‌های بیشتر این فاصله افزایش می‌یابد تا نرخ متوسط آزمون تقریباً از دو درخواست در ثانیه فراتر نرود. به‌دلیل زمان‌بندی تصادفی، فاصلهٔ واقعی دو آزمون و تشخیص خرابی ممکن است تا حدود دو برابر این مقدار، به‌علاوهٔ مهلت پنج‌ثانیه‌ای هر آزمون، طول بکشد. خرابی یک آزمون باعث خروج گره از انتخاب خودکار تا آزمون موفق بعدی می‌شود؛ یک اختلال گذرا هم ممکن است موقتاً انتخاب را عوض کند.

هنگام شروع یا وقتی هیچ نتیجهٔ سالمی در دسترس نیست، balancer از **اولین پروکسی** به‌عنوان مسیر جایگزین استفاده می‌کند، نه اتصال مستقیم؛ البته اگر آن پروکسی هم قطع باشد، برقراری اتصال تضمین نمی‌شود. این موضوع قوانین مستقیم موجود برای مقصدهای خاص، مانند شبکهٔ خصوصی و `cn`، را تغییر نمی‌دهد. مهلت اتصال‌های نیمه‌بسته نیز بیشتر شده است تا بعضی انتقال‌ها زود قطع نشوند. آزمون‌های دوره‌ای سریع‌تر از تنظیم قبلی‌اند، اما ترافیک و مصرف باتری بیشتری دارند؛ برای کاهش آن می‌توانید با ابزار زیر تعداد گره‌های پروفایل محلی را کم کنید.

این سنجش **تأخیر است، نه سرعت دانلود واقعی**؛ Xray صرف دریافت پاسخ HTTP را می‌سنجد و وضعیت ۲۰۴ یا کارکرد همهٔ سایت‌ها را تضمین نمی‌کند. کیفیت اینترنت و پهنای باند سرور، شلوغی و مسیر شبکه در سرعت واقعی مؤثرند. فایل خام `javidsub` همچنان فهرست لینک‌های جداگانه است و انتخاب خودکار balancer فایل JSON را ندارد؛ برخی لینک‌های خام نیز ممکن است در Xray قابل استفاده نباشند.

### سنجش اختیاری سرعت روی شبکهٔ خودتان

برای مقایسهٔ سرعت انتقال واقعی، روی همان دستگاه و شبکه‌ای که از اتصال استفاده می‌کنید، Python و Xray سازگار با پروفایل را نصب کنید و در پوشهٔ پروژه اجرا کنید:

```bash
python speedtest.py --xray /path/to/xray
```

اگر `xray` در `PATH` است، می‌توانید `--xray /path/to/xray` را حذف کنید. ابزار برای هر گره یک تونل واقعی VLESS می‌سازد و به‌طور پیش‌فرض دو بار، هر بار ۲۵۶ کیلوبایت، از `https://speed.cloudflare.com/__down` دانلود می‌کند. امتیاز از میانهٔ سرعت مؤثر (شامل زمان برقراری اتصال) محاسبه می‌شود و تلاش‌های ناموفق امتیاز را کاهش می‌دهند. بهترین گره و حداکثر دو گرهٔ دیگر در فایل جداگانهٔ `final_sub.fast.txt` قرار می‌گیرند. برای داشتن مسیر جایگزین، ابتدا گره‌هایی با نشانی/درگاه متفاوت و حداقل ۸۰٪ امتیاز بهترین گره ترجیح داده می‌شوند؛ اگر کافی نباشند، بقیهٔ جایگاه‌ها بر اساس امتیاز پر می‌شوند. انتخاب کم‌تأخیر بین همین گره‌ها در زمان استفاده فعال می‌ماند. فایل اصلی تغییر نمی‌کند؛ فایل جدید را به‌عنوان **JSON Xray** در برنامهٔ سازگار وارد کنید. اگر هیچ آزمونی موفق نشود، فایل قبلی جایگزین نمی‌شود.

به‌طور پیش‌فرض فقط ۵۰ گرهٔ اول بررسی می‌شوند. اندازهٔ دو نمونه برای هر گره در مجموع **۰٫۵ MiB** است (برای ۲۴ گره حدود ۱۲ MiB)، به‌علاوهٔ سربار اتصال و داده‌های اضافی احتمالی در مسیر؛ این ترافیک از سهم اینترنت و پروکسی مصرف می‌شود. برای بررسی همهٔ گره‌ها از `--max-nodes 0` و برای تغییر تعداد انتخاب از `--top 5` استفاده کنید. پیش‌فرض دو آزمون هم‌زمان است؛ برای کاهش رقابت روی اینترنت محدود می‌توانید `--workers 1` بگذارید، هرچند آزمون طولانی‌تر می‌شود. تنظیمات `--sample-kib`، `--samples`، `--timeout` و `--workers` با `python speedtest.py --help` قابل مشاهده‌اند. اگر مقصد پیش‌فرض در دسترس نباشد یا درخواست‌ها را محدود کند، `--test-url` می‌تواند نشانی فایل دیگری با پاسخ HTTP 200 و حداقل اندازهٔ نمونه باشد؛ در این نشانی اطلاعات محرمانه نگذارید.

نتیجه فقط نمونه‌ای از مسیر و مقصد انتخاب‌شده است، نه تضمین پهنای باند یا دسترسی آینده؛ بعد از تغییر شبکه یا به‌روزرسانی اشتراک دوباره سنجش کنید. این سنجش عمداً در GitHub Actions اجرا نمی‌شود، چون موقعیت و اینترنت runner نمایندهٔ شبکهٔ شما نیست. `final_sub.fast.txt` محلی است، به‌طور خودکار هر چهار ساعت به‌روز نمی‌شود و در `.gitignore` قرار دارد؛ نام‌های خروجی سفارشی را خودتان از Git دور نگه دارید. برای آزمایش این فایل با Xray از همان دستور بخش خروجی‌ها، با جایگزینی نام فایل، استفاده کنید. این فایل و فایل موقت سنجش حاوی مشخصات گره‌ها هستند؛ اطلاعات آن‌ها را محرمانه نگه دارید.

## تست

```bash
python -m unittest discover -s tests -v
```

تست‌ها آفلاین هستند و از سرورهای موقت محلی استفاده می‌کنند؛ تست TLS در صورت وجود OpenSSL یک گواهی موقت تولید می‌کند. برای اجرای تست واقعی Xray با سرورهای ساختگی روی loopback (از جمله انتخاب سریع‌ترین مسیر، خرابی و بازگشت، و پاسخ تأخیری پس از نیمه‌بسته‌شدن اتصال) مسیر باینری و، در صورت نیاز، پوشهٔ فایل‌های داده را مشخص کنید:

```bash
XRAY_BINARY=/path/to/xray XRAY_LOCATION_ASSET=/path/to/assets \
  python -m unittest discover -s tests -p 'test_xray_runtime.py' -v
```

ورک‌فلو همین تست محلی را با Xray تأییدشده اجرا می‌کند؛ این تست سرعت اینترنت واقعی یا سرورهای اشتراک را اندازه‌گیری نمی‌کند.
